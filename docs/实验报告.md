## E5：原始复现

命令（在 `E4-A/`）：

```sh
python3 scripts/lab_cloud.py build --out work/build-01
python3 scripts/lab_cloud.py e5 --out work/e5-01
```

| 项目 | 结果 | 证据 |
| --- | --- | --- |
| 程序输出 | `1` | `work/e5-01/evidence/program-output.txt` |
| 构建 | `make clean` 与 `make -p app` 均成功，构建 stderr 为空 | `work/e5-01/evidence/build-stderr.log` |
| 声明依赖 | `main.o: main.c unused.h`（第 1061 行） | `work/e5-01/evidence/make-db.txt` |
| 实际读取 | `t.16:580: openat(AT_FDCWD, "config.h", O_RDONLY|O_NOCTTY) = 4` | `work/e5-01/evidence/trace/t.16` |

**进程归属**：`t.14` 为 `make -p app`；`t.15` 为 `cc -c main.c -o main.o`；`t.16` 的 `cc1` 是 `cc` 的子进程，成功打开 `config.h`；`t.17` 的 `as` 在同一次编译任务中写出 `main.o`（第 23 行 `openat(AT_FDCWD, "main.o", O_RDWR|O_CREAT|O_TRUNC, 0666) = 3`）。因此 `main.o` 的实际依赖为 `main.c`、`config.h`。

**与论文步骤对照**：论文用 ptrace 跟踪 clean build 并读取 GNU Make 数据库；本实验用 `strace -ff -s 4096 -e trace=%file,%process` 与 `make -p app`，比较范围限定在样例目录内，系统头文件与 `/tmp` 中间文件不计。

**结论**：
- MD：`main.o → config.h`（实际读取、声明缺失）
- RD：`main.o → unused.h`（声明存在、本次构建未读取）
